# 第 3 轮（round3）

这一轮回答三个问题，判据已在路线图文档的 “round3” 一节里先写死：

1. v1 的轮数为什么多了约 15%：是 AGENTS.md，还是扩展？（消融：只带 AGENTS.md / 只带扩展，开发题）
2. 题目更难时，思考档位 low 会不会掉质量？v1 配置包会不会掉质量？（6 道难题，分组 hard）
3. 文件保真闸（edit-fidelity.ts）有没有用：pi 的 edit 工具会悄悄改坏 Latin-1 编码或混合换行的文件，p17 就是为此设计的。

## 怎么跑

```bash
cd ~/pi && tar xzf pi-round3.tgz && cd arena
bash ../round3.sh              # 先看计划不运行：bash ../round3.sh --plan
```

* 全程不需要输入。11 批、约 210 次运行，大约 **10–20 小时**：难题每次要几分钟，现在只能估（每次 5 分钟约 11 小时，10 分钟约 20 小时）。
  可以睡前开跑，第二天看。
* 开跑前把电脑的睡眠设成“从不”（Windows 设置 → 系统 → 电源），屏幕可以关。电脑睡眠会让正在跑的那次超时。
* 想让它在关掉终端后继续：先 `tmux new -s r3`（装了 tmux 的话），再运行上面的命令。
* 中途停了（Ctrl-C、关机、断网）：再运行**同一条命令**，做完的运行会跳过，从断点继续。
* 网关挂了怎么办：连续 3 次拿不到模型的回答，脚本会停下并说明原因（不会把后面几个小时烧在一个坏网关上）；
  确认网关恢复后运行**同一条命令**，受影响的运行会自动重做。偶发的单次失败，脚本在该批做完后自己补跑（最多 2 轮，间隔 60 秒）。
* 每个阶段结束会生成一个结果文件 `arena-results-<时间>.txt`（纯文本，没有密钥）；整轮跑完（或中途停下）最后几行会列出该发哪几个。
  每个阶段的文件一出现就可以先发给我（不影响脚本继续跑），我会边等边分析：阶段 1 约 1 小时后出现，阶段 2 再过 6–12 小时，阶段 3 再过 4–8 小时。

## 里面有什么

```
arena/                评测台 v0.2：新增 hard 组（p13–p18）、每次运行记录安全闸/保真闸/预算守卫的事件、suite --no-pack
v1/                   v1.1 配置包（与 round2 的 v1 行为相同，只多了往 stderr 写拦截日志）
variants/v1-agents/   消融：只有 settings.json + AGENTS.md
variants/v1-ext/      消融：v1 去掉 AGENTS.md（扩展、提示模板、隐藏技能、预设都在）
variants/v1-fid/      v1 加 extensions/edit-fidelity.ts（文件保真闸，实验性）
round3.sh             一条命令跑完所有批次
```

解压会覆盖 `~/pi/arena` 里的代码和题库、以及 `~/pi/v1`；你之前的 `configs/`、`runs/`、`day1/`、`suite/` 和结果文件不动。
