# pi 定制与评测路线图

## 一页纸摘要

**目标。** 把 pi 调成“同模型、同思考强度下，在常见编码任务的多数指标上不输 Claude Code”的 harness，同时守住 pi 最大的卖点：省钱。省钱靠 KV 缓存命中，所以前缀（工具、系统提示、历史）只能追加、不能改写；缓存断一次，那一轮的输入费是正常读缓存的 25–50 倍。

**策略。** 先量后改。先建本地裁判台（12 题，每题至少 3 次，固定版本，按题记胜/平/负），再一次只改一处，先配置层、后扩展层，每次改动都要过缓存回归测试。压缩阈值、预算这类数字用自己的任务量出来，不照搬别人的。

**现状。** pi 能跑：1.3.0 已在本地模拟服务器上跑通真实会话，前缀逐轮严格追加，系统提示加 4 个内置工具只有 1.5k token 左右；经 magpie 的真实会话稳态缓存命中 93–97%。10 月 17 日你已定下模型（开发期 DeepSeek、期末小规模 Claude）、预算与“基线用空白配置”。评测环境已就位：WSL 里的 Claude Code 已升到 2.1.302 并锁定，经 magpie 可用；评测台 arena v0.1 已写好，第一轮（day1）已在你的 WSL 里跑完：magpie 的用量可加、网关缓存稳（命中 95–98%，没有整段未命中）、两边默认强度大体对得上；2 题试点里 pi 比 Claude Code 便宜 17–31%，但小于单次波动（变异系数约 30%），还不能算赢；12 题套件（8 题开发、4 题留出，留出的先不碰）也已做好，第一次套件 suite1（10-23，48 次运行）你也已跑完：47/48 通过，8 题里 7 题全过，题目太容易，分不出高下；pi 对 Claude Code 的成本比（按题取中位数）0.80、轮数比 0.78，但区间都跨过 1，还不能算赢，明确的优势只有冷启动（每次约 $0.00016 对 $0.0026）；数据还点出两个可改的缺口：一次失控（13.4 万输出 token、超时）和 edit 工具约 12% 的失败率。10-24：你确认了两件事（比赛是测量仪器，不是目标：pi 对 pi 做采纳前的护栏，期末再对 Claude Code 终考；能力按 L1–L4 分层），并改了分工：你暂时不日常用 pi，由我先搭一个较靠谱的 v1，你学会了再开始用、再自己动手。第一个 pi 对 pi 实验 think-low 也在 10-24 跑完：只把思考档位降到 low，每题成本约为默认档的 0.61 倍（区间 0.41–0.74）、墙钟约 0.63 倍，24/24 通过、没有失控；但题目太容易，不能证明难题上不掉质量。v1 配置包（短 AGENTS.md、安全闸、预算守卫、斜杠命令、隐藏技能、预设）已在本地模拟网关和评测台运行器上测完，10-25 的护栏对比（round2）也跑完了：两批都 24/24 通过，v1 的成本在噪声内（×1.07），但 LLM 轮数多了约 15%（判据上限是 10%），按事先写死的规则不直接采纳；10-26 到 29 我把第 3 轮要用的东西做完了：6 道更难的题（hard 组）、v1 的两个消融变体、一个实验性的文件保真闸（pi 的 edit 工具实测会悄悄改坏非 UTF-8 和混合换行的文件，p17 专为此设计）、评测台 v0.2 和一条命令跑完的 round3.sh，都在模拟网关上完整演练通过；采纳判据 10-27 在任何数据出现前就先写进了本文档。下一步请你在 WSL 里跑 round3.sh（约 10–20 小时，可中断续跑，全程不用动）。

## 目标与“胜”的定义

“胜”= 同模型、同思考强度、同任务集下，pi 在记分板的多数指标上不输 Claude Code，并有几项明显领先。不要求全胜，也不比模型本身、界面或生态。

| 指标 | 怎么量 | 方向 | 初始假设（基线跑完才算数） |
| --- | --- | --- | --- |
| 通过率 | 每题至少 3 次，隐藏验证器判分 | 越高越好 | 持平或略低；长任务 Claude Code 更稳 |
| 每题成本 | 事件流里的 token × 同一张价目表重算 | 越低越好 | pi 更低 |
| 未命中缓存的输入 token | 每次请求里没被缓存接住的输入 token（Claude Code 的用量按“可加”读）；首个请求（冷启动）与其余请求分开记 | 越高越好 | pilot 实测：冷启动时 pi 远低于 Claude Code（约 1.1–1.6k 对 1.8 万）；其余请求每次约 500–800（pi 略多）；以 suite 的数据为准 |
| 缓存命中率（诊断） | cacheRead ÷（input + cacheRead + cacheWrite） | 只作诊断，不判胜负 | 前缀越大命中率越高（pilot：Claude Code 97%、pi 82%，成本却是 pi 更低），所以不拿它比两边；用来发现缓存断崖 |
| 首轮前缀体积 | 第一次请求里 system + tools 的 token 数 | 越低越好 | pi 更小 |
| 耗时与轮数 | 墙钟秒数、LLM 调用次数 | 越低越好 | 未知 |
| 工具失败率 | 编辑未命中、命令报错 ÷ 工具调用数 | 越低越好 | 未知；pi 的 edit 要求精确匹配 |
| 改动最小性 | diff 行数 ÷ 参考解行数，有无误改测试 | 越低越好 | 未知 |
| 卡死率 | 超时、死循环、需人工介入的运行数 ÷ 总运行数 | 越低越好 | 未知 |

判胜负按题配对：同一题取 3 次的中位数，差距超过 Claude Code 自己两次运行的波动才算胜或负，否则算平。暂定阈值是成本 ±10%、通过率 ±1 题，基线跑完后用实测噪声校准。

**比赛的定位（10-24，你已确认）。** 比赛是测量仪器，不是目标：它回答“这次改动有没有让 pi 变差”（pi 对 pi，采纳前的护栏），和“最后跟 Claude Code 比站不站得住”（期末终考，判据提前写死：通过率不低于 Claude Code、中位成本不高于它、没有超过中位成本十倍的失控、冷启动单列）。它回答不了“裸 pi 缺什么”：题库只能测到题库里有的，缺口要靠真实使用发现。10-24 起分工调整：你暂时不日常用 pi，缺口先由我从评测数据和 pi 的官方示例里找；你开始日常使用后，再用摩擦日志补充。

三条底线，任何改动都不能破：

- 未命中缓存的输入 token 不高于基线（命中率只作诊断），这是 pi 的护城河。
- 通过率不因省钱而掉出噪声范围。
- 不为评测题写死答案：开发集上调参，留出集只在阶段末考一次。

“同强度”不等于旗标同名：pi 的 `--thinking` 与 Claude Code 的 `--effort` 档位未必对应。第一轮校准（calib，每档 3 次）的结果：pi 默认的 medium 在线上变成 high（线上实测只出现 low、high、max 三档），Claude Code 默认是 adaptive thinking 加 effort high，两边默认档大体对得上；各档输出 token 的差距小于同档 3 次之间的波动，只有 Claude Code 的 xhigh 明显更多。所以评测先用默认档对默认档；Claude Code 的 effort 到了网关那头变成什么，从这边看不到，待查。

### Gemini 写的配置：审查结论

这些配置都不破坏缓存前缀（静态文字，或只改新结果、不改旧历史），缓存体检里命中率稳定在 93–97% 也印证了这一点。真正要问的是它们对通过率和轮数的影响。基线一律用空白配置；下面每一项只是候选，实验证明有益才进默认档案。

| 文件 | 做了什么 | 担心什么 | 处理 |
| --- | --- | --- | --- |
| AGENTS.md（约 60 token） | 声明运行环境是 WSL2；项目里没有自己的 AGENTS.md 时，先看清单文件再跑构建与测试 | “先看清单文件”会让每个任务多一轮工具调用 | 候选：当作一个实验，看轮数与通过率 |
| APPEND\_SYSTEM.md（约 157 token） | 四条规则：别整读大文件；日志只留末尾；精准编辑；有歧义先问一个问题 | “有歧义先问”在非交互评测里等于认输；日志只留末尾 80 行会藏掉报错开头，还与 context-guard 重复 | 拿掉“先问”那条；其余三条各当一个实验 |
| context-guard.ts（扩展，不进提示词） | 拦截不带范围的锁文件与依赖目录读取；bash 输出超过 160 行或 8000 字符只留头 40 行与尾 100 行，read 超过 300 行只留头 220 行与尾 40 行，完整输出存到临时文件 | 比 pi 内置截断更严，read 会藏起文件中段，模型可能多读几轮，通过率下降 | 最有价值的候选：当作“更严截断”实验，量每轮新增 token、轮数与通过率 |
| models.json | magpie 的模型清单；开了 sendSessionAffinityHeaders（让网关把同一会话路由到同一后端，有利于缓存命中） | 无 | 保留；DeepSeek 价格填对了（输入 0.15、输出 0.6、缓存读 0.003 美元每百万 token） |

## KV 缓存与省钱护城河

你的直觉大体对：前缀保持不变、历史只追加、压缩要少而狠。要修正三点：“静态”指不改写，不是不更新；压缩阈值该测出来，不能凭感觉；缓存断一次，那一轮的输入费是正常读缓存的 25 倍（Sonnet 5.5）到 50 倍（DeepSeek V4.1 Flash）。

### 三条铁律

| 铁律 | 具体做法 | 依据 |
| --- | --- | --- |
| 前缀逐字节相同 | 缓存按“从开头到某一点”的完全相同前缀匹配，顺序是 tools → system → messages；前面一变，后面全废 | [Anthropic 文档](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)、[Claude Code 博客](https://claude.com/blog/lessons-from-building-claude-code-prompt-caching-is-everything) |
| 历史只追加，动态信息放尾部 | 时间、被改动的文件等放进下一条消息（Claude Code 用 `<system-reminder>`）；序列化要确定，不改写旧消息 | [Claude Code 博客](https://claude.com/blog/lessons-from-building-claude-code-prompt-caching-is-everything)、[Manus](https://manus.im/en/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus) |
| 会话中途不动工具、模型、思考参数 | 改工具定义会让整个缓存失效；缓存按模型隔离，换模型要重建；思考参数变化会让消息缓存失效，部分模型连 system 和 tools 也失效 | [Anthropic 文档](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)、[Claude Code 博客](https://claude.com/blog/lessons-from-building-claude-code-prompt-caching-is-everything) |

### 阶梯式压缩：方向对，阈值要测

压缩会重写前缀，每次都要付一笔固定费用：生成摘要，再把新上下文重新写进缓存。所以“少压几次、一次压到位”比“勤压”便宜，这点你对。但最优阈值并不贴着窗口上沿。我用一个简化模型测算：400 轮、每轮新增 2,000 token、压缩后保留 27k、摘要 3k token；Anthropic 的输出价按基础输入价的 5 倍假设，其余价格取自上表。

- 基准参数下，阈值在 100k–160k 之间任取，总成本都在最优值的 9% 以内；曲线底部很平。但把每轮新增改成 1,000–4,000 token、压缩后保留量改成 15k–50k，最优点会在 60k–300k 之间移动，100k–160k 的最差偏离升到 29%。
- 基准参数下，从不压缩贵 1.5–2.7 倍；每 40k 就压一次贵 1.4–1.9 倍。
- 基准参数下，Claude Code 式的“复用主对话前缀”做摘要，比 pi 默认的“独立请求做摘要”便宜约 20–25%。pi 的文档写明摘要请求会关闭缓存写入，且把对话序列化成文本另发。

两点提醒：这是形状，不是精确数字；若某模型在 pi 里登记的窗口是 1M，默认要到约 98 万 token 才压缩，远在最优点之后，需要用 pi 的按模型压缩覆盖项单独设置。常见任务多在 20–60 轮内结束，大多碰不到压缩，所以它是长任务阶段的杠杆，不是第一优先。

### pi 已经做对的和可以改的

- 已做对：会话是只追加的 JSONL 树；中途改提示词或工具时只追加差异（0.86.0 起）；MCP 连接变化不再改写 codemode 描述（0.99.2）。注意这说的是会话文件：对 openai-completions 这类表示不了“中途改工具或提示词”的提供方，pi 会发完整的转录检查点，前缀照样断（10-24 实测：改技能、改工具、新增 MCP 之后的下一个请求，历史都要整段重新计费，见“能力档案”一节）。
- 已有保温：`cacheWarming` 默认 `streaming`，运行中保温；设为 `idle` 连空闲期也保温。它要求模型声明 `promptCache` 寿命，且预估能省 ≥ $0.05 才触发。
- 已有提示：`showCacheMissNotices` 默认关，打开后会提示明显的缓存未命中。
- 可以改：摘要走“复用前缀”的分叉，做成扩展实验；给大窗口模型设更早的压缩点。
- 前车之鉴：1.2.0 修了一个 bug——扩展触发的回合会在第一次工具调用后撤掉 `before_agent_start` 加的 system 段，每次运行断两次缓存。扩展一动提示词，就可能丢掉护城河。

### 会破坏护城河的清单

- [ ] AGENTS.md、APPEND\_SYSTEM.md 里写了日期、时间、git 状态等每次会变的内容
- [ ] 扩展在 `context` 事件里每轮裁剪或改写历史消息（名叫 context-guard 的扩展要先审这一条）
- [ ] 扩展或包在会话中途增删工具、改工具描述（实测：tool\_search 或 setActiveTools 加载一个工具，tools 数组多一项，其后的前缀失效一次；/reload 只会新增工具，不会关掉已移除的，要关就得重启会话）
- [ ] 中途切换模型或思考强度
- [ ] 工具列表顺序或 JSON 键序不稳定
- [ ] 人停顿超过缓存寿命（Anthropic 默认 5 分钟），下一轮整段重写
- [ ] 网关或代理改写请求，或不回传缓存字段，让你看不见命中率

### 守门：缓存回归测试

每次改 harness 都过两关。静态关：用本地仿真服务连发 N 轮，断言每轮请求体以上一轮为严格前缀，tools、system、旧消息逐字节一致，秒级、免费。动态关：在真实端点跑固定的 8 轮任务，断言第 3 轮起的命中率不低于基线减 2 个百分点。命中率定义同上：cacheRead ÷（input + cacheRead + cacheWrite）。

## 评测方案（裁判台）

先用不依赖 Docker 的本地跑分器，搭一个 12 题的小裁判台；WSL 调大内存后再接 Harbor。每次改动先过缓存回归测试，再看记分板。

### 一次跑分的流水线

1. 取题：把该题的初始仓库拷进一个全新的临时目录；题面文字两边逐字相同。
2. 启动被测 agent：pi 用 `pi -p --mode json --no-session`，Claude Code 用 `claude -p --output-format stream-json`；各自指向全新的空白配置目录，权限全开，不联网，不接 MCP。
3. 记事件流：每次 LLM 调用的 input、cacheRead、cacheWrite、output，每次工具调用的耗时与是否出错。
4. 跑隐藏验证器：记通过与否、diff 行数、有没有改测试。
5. 归一成一行：agent、版本、模型、强度、题、第几次、通过、耗时、各类 token，成本按统一价目表重算。
6. 汇总记分板：逐指标按题配对，判胜、平、负。

### 公平规则

- 同一模型 ID（在日志里核对）、同一端点；强度先在探针题上校准。
- 版本锁定并写进每行结果；Claude Code 用独立的 `CLAUDE_CONFIG_DIR`，pi 用独立的 `PI_CODING_AGENT_DIR`。
- 题面、超时、最大轮数相同；两边交替运行（A B A B），避开服务端波动。
- 每题至少 3 次；先拿 2 道题各跑 5 次测噪声，再定“平局带”。
- 价目表只用一张；DeepSeek 在错峰时段跑。
- 日志全留。网关报错、限流的运行标记后重跑，不静默丢弃。
- 基线用各自的默认工具集，但去掉联网类工具；再另做一轮“工具集对齐”，分开看提示词差异和工具差异。

### 16 GB 笔记本能不能跑 Harbor

Harbor 本身只是 Python 调度器，吃内存的是每个任务的容器。把 WSL 调到约 8 GB / 4 CPU，一次跑 1–2 个小任务可以。Terminal-Bench 4.0 现在不适合：它有 66 题，每题中位估时 4 小时，Claude 级模型每题约 $13–16，还含 GPU 题（[Vals AI](https://vals.ai/benchmarks/terminal-bench-4)）。所以先本地跑分器，后接 Harbor 的小题集。

### 业界怎么比

Artificial Analysis 的 [Coding Agent Index](https://artificialanalysis.ai/agents/coding-agents/comparisons/claude-code-vs-opencode) 同样报每题成本、耗时、轮数、token 和缓存命中率，我们的记分板列与它对齐；它也提醒缓存命中率会随服务商路由大幅变化。它的头条对比里 Claude Code 跑 Sonnet 5.5、Opencode 跑 GLM-5.3，模型不同，所以我们坚持同模型。

- 通过 24/24（默认档 23/24），没有失控：单次运行输出最多约 1.5 万 token（p07），默认档同题的中位数是 2.2 万，默认档那次失控是 13.4 万。总费用 $0.117 对 $0.254；每次运行成本的中位数 $0.0046 对 $0.0065，均值 $0.0049 对 $0.0106（默认档去掉失控是 $0.0072）。
- 成本构成变了：输出 71%、未命中输入 27%、缓存读 2%（默认档 81 / 17 / 2）。输出降得多、轮数降得少，所以输入占比上升。
- 行为也变了：edit 调用 42 次降到 11 次、read 33 次降到 6 次，更多用 bash 直接看和改文件；edit 失败 5/42 变 1/11，工具错误总数 10/295 变 4/179。每题改动大小（最小改动度）与默认档基本一致，只有 p06 从 1.61 降到 1.39。这套题测不出行为变化的后果。
- 对 Claude Code（它默认也是 high）：low ÷ Claude Code，成本 0.49（0.43–0.61）、轮数 0.62、墙钟 0.52、输出 token 0.52，8 题全部更低。这不是同强度的比较；同强度要另跑一批 Claude Code 的 low（`--cc-effort low`）。
- 局限：题目已饱和（8 题里 7 题全过），“low 不掉质量”只在这个难度上成立；24 次运行看不到约 1/24 的失控尾部；还没有同配置的重复批（A/A）来量批间漂移，round2 补上。
- 结论：思考档位是目前量到的最大杠杆（成本约 −40%，墙钟约 −37%，这套题上没看到质量损失）。v1 默认定 low；难题上的质量等更难的题来回答。

### 能力档案：装得多、开得少

你提的想法：把常用的扩展、技能、提示模板、工具、MCP 先装好，默认关着，任务开始前判断开哪几个。结论：方向对，pi 已经自带这套机制；要改的是“什么时候切”和“谁来判断”。

| 类型 | 装了不用，占前缀吗 | 要不要逐个选 | 机制（pi 1.3.0 文档） |
| --- | --- | --- | --- |
| 提示模板 | 不占；你敲 `/名字` 才展开 | 不用，全装 | prompts 目录；`--prompt-template` |
| 技能 | 只占名称、描述与路径，正文按需读；装太多会拉长前缀、让选择变差 | 基本不用；可用 `disable-model-invocation` 隐藏 | skills 目录；`--skill` |
| 只挂钩子、不注册工具的扩展 | 不占 | 不用 | `extensions` 设置里的 `+`、`-`、`!` 过滤；`-e` |
| 注册了 direct 工具的扩展、direct 的 MCP | 每个工具的定义都占（pi-web 实测多出约 3.3k token） | 要选 | `--tools`、`defaultTools` 的 `+`/`-`、`-xt` |
| 设成 codemode 或 deferred 的 MCP 与扩展工具 | codemode 只占一个工具；deferred 平时不占，用时由 tool\_search 加载 | 少选：用懒加载代替开关 | `exposure` 设置；`codemode`、`tool_search` |
| AGENTS.md、APPEND\_SYSTEM.md | 全占 | 要选 | 每个档案放自己的版本 |

**切换的规则（实测加文档）**

- 一次工具集变化 = 一次整段重计费。模拟服务器实测：tool\_search 或 setActiveTools 在会话中途加载一个工具，tools 数组多出一项，该请求的仿真命中率只有 48%，下一个请求回到 96%。代价与当时的上下文成正比：第 1 轮（约 2k token）几乎为零；上下文 10 万 token 时约等于 50 个正常轮次的输入成本（DeepSeek）。
- `/reload` 只会把新加进 `defaultTools` 的工具开起来，不会关掉已移除的（settings.md）：“取消注释”可以 reload，“注释掉”要重启会话。
- 所以：档案在会话开始前定好；想换档案就开新会话，需要接力就让它先写一份交接摘要。
- Anthropic 自家的工具搜索声称不破坏提示缓存（被推迟的工具不进初始提示，搜到后才展开）；pi 的 tool\_search 在 openai-completions 这条路径上实测是改 tools 数组，要按上面的规则对待。

**谁来判断（按成本从低到高）**

1. 你自己：看一眼清单，5 秒，零 token。
2. 规则：任务里的关键词对应档案（如“查 issue、查网页”加 web 档）。
3. 会话外的一次小模型调用：输入能力清单（每项一句话、前缀成本、副作用）加任务描述，输出要开的清单，再用清单校验；约 1–2k token，DeepSeek 下不到 0.001 美元。评测里这一步必须自动化，并单独记账。

**怎么验证它值得**

- 三组对照：固定精简默认、全开、路由选档。看通过率、总成本（含路由那一步）、轮数、前缀 token、选档准确率（对照人工标注）。
- 顺序：空白基线、精简默认、逐个加包、最后才上路由。现在先装一堆，后面的增量就没法归因。
- 安全：每个第三方扩展、技能、MCP 都是用你的凭据运行的任意代码，先读源码再装，锁版本。
- 旁证：Anthropic 的数据里，5 个 MCP 服务器 58 个工具的定义约 55k token；改用工具搜索后，Opus 4 的 MCP 评测准确率从 49% 升到 74%，Opus 4.5 从 79.5% 升到 88.1%。来源：[Anthropic 工程博客](https://anthropic.com/engineering/advanced-tool-use)。

**实测（10-24）：开一项能力，前缀多多少。** 在容器里用模拟网关抓 pi 1.3.0（openai-completions 路径）的第一个请求，逐项开关；基线 5998 字符，对照 suite1 里 DeepSeek 实测的首请求 1646 token，折算约 3.6 字符/token（估算，±15%）。MCP 的数字用的是我写的假服务器（每个工具的描述约 45 词加 3 个参数），真实服务器每个工具常有 100–400 token。

| 配置 | 前缀增量（估算 token） | 说明 |
| --- | --- | --- |
| 基线（read / bash / edit / write） | 约 1.65k | 对照实测 1646 |
| `--tools read,bash`（或 `-xt edit,write`） | −0.63k | 工具少，系统提示里的规则也变短 |
| 加 grep / find / ls（`defaultTools`） | +0.61k | 每个工具约 200 |
| 加 codemode | +0.60k | 已声明工具的描述还会被追加一句“可在脚本里调用” |
| 技能（可被模型调用） | 固定 +0.23k，每个 +45 | 描述约 170 字符；描述越长越多 |
| 技能加 `disable-model-invocation: true`；提示模板 | 0 | 不进前缀；用 `/skill:名字`、`/模板名` 才展开 |
| MCP，默认暴露（codemode） | +0.66k | 与工具数无关：12 个和 40 个相同 |
| MCP，`deferred`（tool\_search） | +0.26k | 用时才加载，加载那一刻断缓存 |
| MCP，`direct`（逐个声明） | 每个工具约 +190 | 12 个 +2.2k；40 个 +7.4k |
| MCP 设 `enabled: false`、`--no-mcp`、`--no-skills` | 0 | 项目 `.pi/mcp.json` 可以覆盖用户级的 `enabled` |
| 全家桶：20 技能 + MCP（codemode）+ grep/find/ls | +2.45k | 约为基线的 2.5 倍 |

怎么读这张表：缓存读价 $0.003/百万 token，全家桶多出的 2.45k token 每个请求约 $0.0000074，10 个请求的任务多花不到 1%（pi 的中位成本约 $0.0065），缓存读只占 pi 总成本的 2%。所以静态前缀的税主要在两处：冷启动（2.45k × $0.15/百万 ≈ $0.00037，一次）和前缀被中途改动（见下）。工具选错、轮数变多这类行为上的副作用，这张表量不出，只能 A/B。

**实测（10-24）：会话中途改配置，下一个请求还能命中多少前缀。** 模拟网关按 tools → system → messages 的顺序算前缀。会话里先有约 3.7k token 的历史（6 次脚本化的工具调用），再用扩展命令改配置并 reload，对比改动前最后一个请求与改动后第一个请求。真实会话的历史更长，保留的比例更低。

| 改动 | 还能命中的前缀 | 说明 |
| --- | --- | --- |
| 没改东西的 reload（对照） | 100% |  |
| 增删一个技能后 reload | 31% | 只改系统提示的尾部，但其后的整段历史都失效 |
| 加一个内置工具（`defaultTools` 加 grep），或 `setActiveTools` | 14% | tools 数组变了 |
| 新增 MCP 服务器（默认暴露，会激活 codemode） | 2% | 已声明工具的描述都被改写，从第一个工具起就断 |
| `defaultTools: ["-edit"]` 后 reload | 100%（但无效） | 工具并没有被关掉：reload 只启用新增的工具，不关闭被移除的；要关就开新会话 |
| 会话中途 `/skill:名字` | 100% | 技能正文追加在新的用户消息里，前缀不动：零成本的“中途开关” |

pi 自带的几种“开关”，按缓存风险排序：

- 追加式，零风险：`/skill:名字`、`/模板名`、`!命令`；用 codemode 调 MCP 工具（工具声明不变）。
- 开局决定，零成本：`--tools`、`-xt`、`--no-skills`、`--no-mcp`、`-e`、`--skill`；项目的 `.pi/settings.json`、`.pi/mcp.json`（交互模式会问是否信任；print、JSON、RPC 模式默认不加载，要加 `--approve` 或设 `defaultProjectTrust: "always"`，10-24 实测）；`pi config`；示例扩展 `preset.ts`（`--preset` 与 `/preset`，可切模型、思考档位、工具、附加指令）。
- 中途改，整段重计费：增删技能后 reload、加工具、新增 MCP、`tool_search` 加载、`setActiveTools`。第 0 轮做几乎免费；任务进行中做，一次约等于一个任务的成本（DeepSeek，3 万 token 历史约 $0.0044）。
- 让 pi 帮你配置：按项目一次性做（看过仓库后生成 `.pi/settings.json` 与 AGENTS.md），不要每个任务预测一次。一次小模型判断约 $0.0005–0.001（粗估），比“一直开着”的税（约 $0.00007/任务）贵一个数量级。

**分层（10-24，你已确认）。**

1. L1 固定核心（始终开）：4 个默认工具，加一份短而静态的 AGENTS.md；grep / find / ls 等先 A/B 再入选。
2. L2 懒目录（装着不管，成本接近 0）：技能（描述写精炼）、MCP（codemode 暴露）、提示模板。
3. L3 隐形、手动：`disable-model-invocation` 的技能加 `/skill:`；扩展命令。
4. L4 重、急、危险：direct 暴露的大工具集、能写外部系统的 MCP、会改系统提示的扩展。会话开始前由人（或项目配置）决定，不由模型每次预测。
5. 待 A/B 验证的假设：“基础能力”更可能来自指令（AGENTS.md）、护栏（防失控、edit 可靠性）和思考预算，而不是更多工具。

### 上手清单：一个杠杆一个练习（10-24）

目的是学会定制，不是比赛（10-24 起：这些练习等 v1 定稿、你读完教程之后再做）。每项 10–20 分钟，在一个真实项目里做；pi 的文档与示例路径写在它系统提示的 docs 段，直接问 pi 就能拿到。

1. AGENTS.md：在项目根目录写不超过 10 行（怎么跑测试、不要改什么、提交约定），启动 pi，看启动头是否列出它，再看 pi 照不照做。内容要静态，不写日期与状态。
2. 隐藏技能：写一个 `SKILL.md`（name、description、`disable-model-invocation: true`），放进 `~/.pi/agent/skills/<name>/`，`/reload`，用 `/skill:名字 …` 调用；再去掉 disable，用 `/session` 对比前后的 token 统计。
3. 项目级配置与信任：在项目里建 `.pi/settings.json`（例如 `defaultTools` 加 grep、find、ls），交互模式启动会问是否信任，`/trust` 可保存决定；`pi -p` 不加 `--approve` 时项目配置会被忽略。
4. MCP：`pi mcp add` 接一个本地 stdio 服务器，用 `/mcp` 看暴露方式，把 `exposure` 在 `codemode`、`deferred`、`direct` 之间改一遍，对比新会话里 `/session` 的上下文用量。
5. 一个小扩展：把 `examples/extensions/` 里的 `permission-gate.ts` 或 `protected-paths.ts` 复制进 `~/.pi/agent/extensions/`，改一行规则，`/reload`，看它拦住什么。
6. 预设：把 `preset.ts` 放进扩展目录，写 `presets.json`（plan：只读工具；implement：默认工具），用 `--preset` 启动，体会“开局选档”。
7. 思考档位：同一个小任务分别用 `/thinking low` 与 `/thinking high` 跑，对比 `/session` 的 token 与费用。
8. 摩擦日志：每遇到一次“要是 pi 能……”或“它又……了”，记一行（场景、卡点、怎么绕）；同一类卡点出现第二次，才进候选清单，再去做变体和 A/B。

## v1 与教学轨道（10-24 起的主线）

10-24 你把分工改了：暂时不日常用 pi，也不想自己折腾；由我先搭一个较靠谱的 v1，你学会了再开始用、再自己动手。所以主线从“你用、记摩擦日志”改成“我搭、我测，再教”；摩擦日志留到你开始日常使用之后。比赛仍是护栏（采纳前的 pi 对 pi 回归），不是目标。

### v1 里有什么

v1 是一个目录，镜像 `~/.pi/agent/`：既能 `bash install.sh` 装进你的 pi，也能直接交给评测台的 `--pi-config`。原则是前缀几乎不花钱：只有一份短 AGENTS.md 进系统提示（多约 360 token），其余是代码，或按需才加载的文件。

| 部件 | 做什么 | 前缀 token | 怎么关 |
| --- | --- | --- | --- |

记分约定：

- 通过 = 评测台的 pass（可见与隐藏检查全过、未超时、未改受保护文件）。
- 得分 = 验证器的“通过的检查项占比”（报告里的 checks 列）；改了受保护文件记 0；验证器没给出计数的失败记 0；超时的运行按最终工作区的验证结果计分，另外单独数超时。

- 基础设施错误（标 I）先重跑；仍有的剔除并报数。
- 噪声：开发题基线有三批（think-low、think-low-b、think-low-c），A/A 差距 = 三对两两差距的平均。难题基线有两批（hard-low、hard-low-b），合并成 hard-LOW（36 次）；NOISE\_S = 两批平均得分之差的绝对值，S = max(0.05, 1.5 × NOISE\_S)。难题的通过数一律折算到每批 18 次。

采纳判据：

1. 开发题的轮数与成本（阈值与 round2 相同）。基线 = think-low、think-low-b、think-low-c 共 72 次；v1 合并 = v1 与 v1-b 共 48 次。T = 1 + max(0.10, 1.5 × A/A 差距)，成本与轮数各算各的；成本用去掉冷启动影响后的值，未调整的值只报告、不参与判定。(a) v1 合并的轮数比 ≤ T\_轮数，则“多 15%”主要是噪声，v1 过轮数关；超过则是真的变多。(b) 归因：abl-agents 与 abl-ext 各自的轮数比，超过 T\_轮数 的那一半是原因；两者都超是都有份；都没超是“拆开后各自不显著”（交互或噪声）。(c) 通过：失败数 ≤ 基线失败率 × 该批次数 + 2；工具错误：每次运行的均值 ≤ 1.5 × 基线均值 + 0.08。
2. 难题上的思考档位默认值。默认保持 low，除非 hard-blank 同时满足：平均得分比 hard-LOW 高 ≥ max(0.10, 1.5 × NOISE\_S)，且通过数比 hard-LOW 多 ≥ 3（折算到 18 次）。满足则默认改回 high（去掉 settings 里的 defaultThinkingLevel），并加一个 low 的“省钱”预设；不满足则默认 low，deep 预设保留。两种结果都报成本比与墙钟比。
3. 部件取舍。AGENTS.md 与扩展组各自独立判断，保留须同时满足：(a) 难题不更差：该部件的难题批相对 hard-LOW，平均得分差 ≥ −S，通过数差 ≥ −2；(b) 开发题成本比 ≤ T\_成本，通过数与工具错误满足 1(c)；(c) 开发题轮数比 ≤ T\_轮数，或该部件在难题上“有益”（平均得分差 ≥ +S，或通过数差 ≥ +3）。不满足的部件移到 optional/，默认不装，写进教程当作“量过没赚”的例子。另看整包 hard-v1：若它“有害”（得分差 < −S 或通过数差 ≤ −3），而两个部件各自都过关，按交互处理，只装难题得分较高的那个。四种组合（都装、只 AGENTS.md、只扩展、都不装）都有对应的批，不再另跑确认。
4. 文件保真闸。无闸对照 = 在 low 档、没有闸的 5 批里 p17 的 15 次（hard-low、hard-low-b、hard-v1、hard-agents、hard-ext）；有闸 = hard-fid 的 6 次。纳入 v1 的条件：通过率（有闸减无闸）≥ 0.30，且 p17 平均得分提高 ≥ 0.10。闸只在文件不是 UTF-8 或换行混合时触发；已静态扫描全部题库，会触发的只有 p17 的两个文件和留出题 p12 的一个 CSV 夹具，所以本轮不单独检验误拦，靠单元测试。不满足则作为可选件保留，“pi 的 edit 会改坏这类文件”这个发现留作教材。
5. 守卫的误伤。逐条看所有批里安全闸、保真闸拦下的命令和预算守卫的事件（评测台每行记 guard 字段）。任何一批的误拦超过每 24 次运行 1 次，或预算硬中止超过每 18 次难题运行 1 次，先改规则或额度再采纳；是不是误拦由我读命令判断，并写出理由。

不会事后改的东西：以上阈值、题目集合、记分方式在看到任何第 3 轮数据前固定。难题的难度若与目标差很多（某题所有批都全过或全挂），记为发现，不换题、不改判据；另外报告一个“只含合并通过率在 10%–90% 之间的题”的视图，只作探索，不参与判定。难题每批 18 次，平均得分的批间差约 0.05–0.07 就是噪声量级，所以“不更差”是护栏，不是等价证明；规则的方向是把举证责任放在更贵或更复杂的一方（high 档、多出来的部件、保真闸），噪声范围内的差别一律取简单便宜的那个。结论只对 DeepSeek V4.1 Flash 和这 14 道题有效，不外推到 Claude 或真实项目。

### 教学轨道（v1 定稿后开始）

| 课 | 讲什么 | 你照着做 | 依据（本文档里的实测） |
| --- | --- | --- | --- |

### 升级演练

1. 固定：pi 用 `npm i -g @earendil-works/pi-coding-agent@<版本>` 安装并记录；Claude Code 升到 stable 渠道后设 `DISABLE_AUTOUPDATER=1`；版本号写进每条评测结果。
2. 看变更：发版时读 changelog 的 Breaking Changes、Caching、Compaction 三段；用 `npm view @earendil-works/pi-coding-agent dist-tags` 看有没有新版。
3. 隔离试装：在独立的 `PI_CODING_AGENT_DIR` 里装新版，跑缓存回归测试加 3 道冒烟题。
4. 过关再升，并写入实验日志：旧版 → 新版，指标变化。
5. 写扩展的纪律：只用文档里写明的事件和 API；每个扩展配一个“契约测试”，用 `--mode json` 装载并断言行为；语义变过的事件（如 `before_agent_start`）一律当高危处理。
