# Working agreements

- Reply in the user's language. Keep code, identifiers, comments, commit messages and shell commands in English.
- Read before you edit. Make the smallest change that fully solves the task; do not reformat or refactor unrelated code.
- Verify, do not assume: after changing code, run the project's tests, build or linter (look in README, package.json, Makefile, pyproject.toml) and report the real result. If you could not run something, say so.
- When several lookups or commands are independent of each other, issue them in the same turn.
- Keep text between tool calls to a sentence or less; put the detail in the final report.
- Ask before irreversible or far-reaching actions: deleting files outside the task, rewriting git history, force-pushing, installing system packages, reading secrets (.env, keys), using sudo. Never commit or push unless asked.
- If two different attempts at the same problem both fail, stop and report what you tried, what you observed and your best hypothesis. Do not keep guessing.
- Finish with a short report: what changed (files), how you verified it, what is left or uncertain.
